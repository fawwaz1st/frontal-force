fix: desktop grenades work, slide carries momentum, dash stops misfiring

Three fixes from a professional playtest rating the game 0/10. All three
are wiring or tuning defects the test suite could not see, because every
field is declared and assigned and every gate is green.

GRENADES WERE UNREACHABLE ON KEYBOARD/MOUSE.
  Input.grenadeHeld was only ever assigned from TouchControls, so it was
  permanently false on the primary control scheme. The whole subsystem --
  cooking, frag/smoke/EMP, the throw arc -- was dead code for a keyboard
  player. KeyG cycled the kind and did nothing else, while the README
  documented "G: hold to cook, release to throw".
  Now: G holds to cook, releases to throw, and a tap under 220 ms cycles
  the kind without spending a charge. The tap needed its own InputFrame
  flag (grenadeTap) because even a 60 ms press starts cooking, so the
  release branch would otherwise fire a dud. Verified in a real browser:
  tap keeps charges and cycles frag->smoke, hold cooks to 0.76, release
  throws and spends one charge.

THE SLIDE WAS SLOWER THAN SPRINT FOR ALMOST ITS WHOLE DURATION.
  Entry target was 8.5 m/s over 0.65 s at accel 2.2; sprint is 7.65 m/s.
  The velocity crawled toward the target, so the slide beat sprint for
  ~0.2 s and then fell below it -- a dodge button that slows you down.
  Now SLIDE_SPEED 8.2, SLIDE_TIME 0.85, slide accel 9, so the slide is
  clearly faster than the sprint it came from for its whole duration.
  Added the slide-cancel: jumping out of a slide ends the slide and keeps
  the horizontal momentum. The old code blocked jumping while crouched,
  which switched the whole movement chain off.

SHIFT-RIGHT FIRED THE DASH BY ACCIDENT.
  Q and ShiftRight both triggered it, so tapping either Shift key while
  sprinting dashed -- the classic "my ability goes off by itself" report.
  Q is the one dash key. Both Shift keys sprint, as documented.

ROTATION MODE DID NOT DISCLOSE ITS ONE RULE.
  It swaps the weapon on every kill, and nothing told the player, so the
  first ROTATOR wave read as the "weapon switches by itself" bug. The
  wave banner now names the rule.

README control table corrected: G is grenade, F/V are melee (the old
table claimed F cycled grenades, which was never true), Q is dash.

Gates: check clean, check:self 212/212, check:runtime 30/30, build clean.
