# AGENTS.md — project learnings

## Tooling quirks (Codebuff)
- `write_file` with long content can silently corrupt output (dropped tokens mid-file, e.g. `PROJECTILE_POOL` → `PROJECTILE pool`, `this.rafId` → `thisrafId`, duplicated CSS selectors). Always re-read a freshly written file before typechecking; prefer `str_replace` for surgical edits.
- Playtest automation: the preview tab's rAF fully suspends when the panel is not visible — HUD state freezes and `preview_evaluate` returns stale values. Validate "frozen game" observations only while the panel actually renders.
- Pointer lock is denied in automation and Esc is swallowed by the browser: drive pause with `KeyP` (alias wired in Input.ts), dispatch synthetic `KeyboardEvent`/`MouseEvent` on `document`, and spoof `document.pointerLockElement` via `Object.defineProperty` to exercise firing paths. Note the game no longer REQUIRES the lock: if it does not land within 320 ms the input layer falls through to touch look (`touchLook`), and mouse paths gate on `lockedNow` (lock OR touch), not `locked`.
- A SYNC terminal dev server dies when the user interrupts the turn. Start long-lived servers with `nohup ... & sleep` and verify with `curl http://127.0.0.1:5199/` (plain `localhost` was intermittently unreachable from the browser; `127.0.0.1` works).

## Build / config
- `npm run check` = `tsc --noEmit`; `npm run build` = check + vite build. tsconfig is strict-plus: `noUncheckedIndexedAccess` (indexing returns `T | undefined`), `exactOptionalPropertyTypes`, `verbatimModuleSyntax` (type-only imports must use `import type`).
- Vite serves on 0.0.0.0:5199 during sessions; legacy `dist/` was committed in the baseline but is now gitignored.

## Architecture decisions
- Data flow is one-way: `Input → Game (orchestrator) → sim modules → HudState → Hud (DOM)`. Sim modules never touch the HUD; the HUD never mutates sim state. Weapon ownership (ammo/reload/switch/hitscan) lives in `combat/WeaponController`, not Game.
- HUD full-screen overlays (`[data-menu]`, `[data-pause]`, `[data-death]`) are `inset:0; pointer-events:auto` — they MUST be created with the `hidden` class or the last one in the DOM swallows every click on the page (this bit us once).
- Pause triggers on pointer-lock loss as well as Esc/P; pointer lock can also drop on tab switch. `resume()` re-pauses after 300 ms if the lock does not return (browsers rate-limit re-lock after Esc).
- Enemy kills leave fading corpses (`CORPSE_LIFE` 6 s, scale-y collapse) before disposal — `aliveCount` only counts non-dead; radar uses `forEachLive`.
- Radar/damage-arc rotation: player-local forward = `-(dx·sin yaw + dz·cos yaw)`, right = `dx·cos yaw − dz·sin yaw`. Damage-arc angle = `atan2(dx, −dz) + yaw` (arc wedge points screen-up at angle 0). Verify sign conventions with the yaw=0 basis vectors before "fixing" mirrored blips.
- Enemy hits carry the attacker position through `EnemyManager.onPlayerHit(damage, from)` so the HUD can show directional damage arcs; `player.onDamaged(from)` forwards it.
- Escort bots live in `ai/Ally.ts` (own targeting/LOS, bolt interception, 18 s redeploy); cover claims are allocated by `ai/Tactics.ts` — a deterministic spot scorer (travel, engagement range, verified LOS) keyed by `tacticalId` that releases a claim on death, dodge, LOS loss, and retreat.
- **`combat/Combatant.ts` is the AI seam**: a `CombatTarget` interface (`targetId`, `team`, `threatRole`, `position`, `velocity`, `eyeHeight`, `hpFraction`, `targetable`, `aimPressureAt`, `receiveDamage`) plus the pure scoring helpers (`threatScore`, `grudgeAt`, `THREAT_WEIGHTS`, `GRUDGE_WINDOW`). The player and both bots implement it; `Game` pushes them into `enemies.targets` (`PlayerTarget` adapter keeps `Player` renderer-only, `threatRole` 1.0 vs the bots' 0.45). Adding a third friendly type costs one registration.
- Enemy target selection is a utility score (proximity 0.30, role 0.20, aggression 0.20, fragility 0.15, aimPressure 0.15) with stickiness: `RETARGET_INTERVAL` 0.25 s + `RETARGET_STAGGER` 0.06 s per roster index (wrapped at 32 — `tacticalId` grows forever, and an unwrapped offset stretches the re-score period into seconds), `TARGET_SWITCH_HYSTERESIS` 1.25×, `TARGET_COMMIT_TIME` 1.5 s. Perception uses two radii (sight vs keep-sight at 1.2×) to kill boundary flicker; alerted memory `SEARCH_MEMORY` 6 s; `markAggressorForTarget` propagates a hit to the squad in one O(n) pass.
- Projectiles carry `targetId` (the intended victim), so a bolt only damages the friendly it was aimed at; escort interception is a segment test against `interceptors`, keyed off that same intended victim.
- Escorts are NOT leashed and NOT player-anchored: each bot owns a HALF of the arena, assigned by `assignSectors` every `SECTOR_TICK` 2.5 s on whichever axis the live enemy cloud is more spread along (tie → X), because two bots with a shared objective simply walk to the same cluster. `ownerPos` is discarded by `Bot.update` (`void ownerPos`) and kept in the signature on purpose. A respawn walks in from the bot's OWN sector edge (`ROAM_LIMIT - RESPAWN_INSET`), never from the player. Roles are auctioned squad-wide every 2 s (`ROLE_AUCTION_INTERVAL`) — the bot nearer its victim flanks (standoff `FLANK_STANDOFF` 8 m), the other overwatches (standoff `OVERWATCH_STANDOFF` 15 m, band 10–20 m) — with opposite orbit signs (`side = idx === 0 ? 1 : -1`). Retreat under `RETREAT_HP` 0.30, re-engage at `REENGAGE_HP` 0.55, hard ceiling `RETREAT_MAX_TIME` 8 s, and only if a threat is inside `RETREAT_TRIGGER_RANGE` 20 m. The role split is re-enforced after updates so a redeploy can never mirror the pair.

## Testing seams
- Two suites, on purpose. `npm run check:self` asserts WIRING by reading source text (fast, no imports, catches "the constant is gone"); `npm run check:runtime` transpiles and EXECUTES the real modules (`Player`, `Run`, `Upgrades`), so it catches a sign error or a clamp in the wrong place. A regex cannot prove `(30 - 10) * 0.5 === 10`.
- The runtime suite emits into `.runtime-build/` INSIDE the project (gitignored) and deletes it after. It must not emit to the OS temp dir: the harness imports `three`, and Node resolves bare specifiers by walking up from the importing file, so a temp path has no `node_modules` above it.
- `scripts/self-check.ts` asserts the README's own test count. Adding tests fails the suite until the README line is updated — that is deliberate, not a bug.
- Node's `--experimental-strip-types` rejects TypeScript parameter properties (`constructor(private readonly x: T)`), and `--experimental-transform-types` does not exist in Node 26. Transpile with the project's own `tsc` when a test must import a class.

## Browser probing (no browser provider in this environment)
- Edge is at `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`; drive it headless over CDP (`--remote-debugging-port=9333`) and talk to `/json/list` with `fetch`. There is no Playwright/Puppeteer/esbuild in the project.
- **The Chromium `--user-data-dir` must live OUTSIDE the project.** Vite watches the project tree, and a live Chromium profile is open SQLite databases: the watcher throws `EBUSY ... Network\Cookies` and KILLS the dev server mid-probe. Symptom: `ERR_CONNECTION_REFUSED` from the page after the first navigation.
- Start the dev server in the SAME process as the probe and kill it at the end. A detached server dies when the tool call returns.
- `Runtime.enable`/`Network.enable` only observe requests made AFTER they are enabled: navigate to `about:blank`, then navigate to the game, or the boot failure is invisible.
- Headless Edge reports `typeof navigator.gpu !== 'undefined'` but logs "No available adapters" under `--disable-gpu`; the WebGPU renderer still initialises and renders (canvas has non-zero size). Do not treat the adapter warning as a failure.
- Drive gameplay by calling the real seams on `window.__game` (`hud.onStart()`, `onDeath()`, `applyRunMods()`) rather than synthesising input; the orchestrator is exposed for exactly this.
- Wait for `enemies.aliveCount > 0 && waves.wave > 0` before probing anything combat-side. The first wave spawns after the deploy intermission, and a roster of 0 makes every combat probe silently skip.
- `Game` pushes some run modifiers into systems on the SIMULATION TICK (`enemies.shieldBreakBonus`, `sightMul`), so a probe that sets them must yield ~400 ms before reading them back.

## Game tuning / behavior
- Fixed-timestep loop (60 Hz) has a catch-up guard: max 5 sim steps per frame, backlog dropped beyond that — long stalls degrade to slow motion instead of freeze-spiral.
- Headshots (hit point in top ~22% of enemy capsule) deal 2× damage; wave-clear bonus is wave×250.
- Five modes in the `Waves.ts` MODES table (standard/blitz/onslaught/rotator/overrun); only OVERRUN is `endless: true` — 24-alive cap, HP ×1.12^(wave−1) capped ×40, speed capped ×1.30, spawn cadence ×0.94^(wave−1) floor 0.25 s, ×1.5 score, no cleared plate.
- Warden armour: ±60° frontal cone halves damage and charges a 6-block guard meter (break = 1.2 s stagger, meter reset); flank shots ×1.5; shield down during the 0.45 s wind-up.
- Kill combo: 3 s window per kill, `min(1 + floor(streak/2), 8)`, one tier lost per 0.5 s after the window lapses, hard reset on player damage.
- Landing above 6 m/s vertical impact fires a white shock ring + smoke puff (`Game` `player.onLanded`).
- Saves use schema `version: 1` with additive hydration — legacy payloads keep working, unknown keys dropped, every number `finite()` + clamped. `totalKills`/`totalRuns`/`totalWavesCleared`/`killsPerMode` are lifetime counters; OVERRUN keeps its own `bestWaveOverrun` (localStorage key `frontal-force.v1`).
- **Ten weapons** in `WEAPON_ORDER` (`ar, smg, shotgun, rail, dmr, lmg, pistol, launcher, beam, burst`) — `HudState.weaponIndex`/`weaponName` drive the equipped-slot ring plus an `n/3` counter; Digit1–3 and the wheel both index the same list. Launcher splash = `blastRadius` 4 m falling linearly to `blastFloor` 0.35, on a SEPARATE `selfBlastRadius` 3.2 m with `MAX_SELF_BLAST` 35 (without the cap the endless ×40 damage ramp turns a point-blank rocket into suicide). Burst fires `burstCount - 1` follow-ups at `BURST_ROUND_INTERVAL` = 1/4.8 (≈288 rpm), and `switchTo`/`rotate` clear `burstLeft` so a swap never leaks rounds into the new gun.
- **Touch is a first-class scheme, pointer lock is not a gate**: `input/TouchControls.ts` uses PointerEvents with a `pointerId` map (never TouchEvent), free-drag look on the right (0.25°/CSS-px, ×0.45 ADS), a floating-origin stick on the left (0.18 dead zone, 62 px radius, 45 % of the width), and 10 buttons (`fire`, `jump`, `aim`, `melee`, `dash`, `grenade` on the right action grid, `sprint`, `crouch`, `reload`, `cycle` on the left utility row) hit-tested before the stick/look zones. **Placement is SOLVED, not tuned**: `layout()` derives a cell step from the button radii, counts the columns and rows the safe viewport actually admits, and shrinks the base size (32 nm floor → 61 px tap) until the whole grid fits, so no viewport can produce an overlap or an off-screen button. Both clusters read one derivation (`cellStep`, `smallR`), so they cannot disagree about tap size. The HUD must draw all ten ids — a declared ButtonId that is hit-tested but never drawn is a touch player's ability they cannot find, which is exactly what happened to `dash`/`grenade`/`melee`. `Hud.layoutTouch()` positions the overlay from `TouchControls.buttonsForRender`, so drawn rects ARE the hit-rects, and charge pips (`data-tpip`) mirror the dashboard plates off the same `HudState` snapshot. `Input.requestLock()` arms a 320 ms timer — if the lock has not landed, `touchLook` flips and the game runs lockless.
- **Adaptive quality** (`core/quality.ts`): boot tier from `userAgentData.mobile`/UA + `deviceMemory` + `hardwareConcurrency`, then `FrameTimeGovernor` on a 30 fps budget (HIGH 40 ms step down, LOW 26 ms step up, RESET 33 ms, 5 s sustained-fast gate before recovery). Presets cap `devicePixelRatio` (low 0.75 no AA no shadows / medium 1.0 no AA 1024 / high 1.5 AA 2048) and `presetFor()` adds a +0.5 desktop bonus. `resolveTier(setting, detected)` lets an explicit LOW/MEDIUM/HIGH setting override AUTO.
- **Pickups are gated on real need** (`world/Pickups.ts`): `tryCollect(pos, usable)` takes a predicate from `Game` rather than deciding itself, because only the orchestrator knows the player's health and the weapon reserves. A health drop walked over at full HP STAYS on the ground instead of being destroyed — consuming a reward that grants nothing is a punishment for winning the fight that produced it, and it is invisible. Stations obey the same rule, which is strictly better for them: a station touched at full health stays standing instead of vanishing into its 14 s respawn timer. `WeaponController.needsAmmo()` reads the RESERVE cap, not the magazine, so a full mag with a half-empty reserve still takes ammo.
- **Loot is on the radar as a diamond** (`Game.buildRadar` → `Hud.drawRadar`): drops are appended AFTER the enemies so a 24-enemy wave cannot starve the pool of the thing the player is looking for. Shape carries the category (diamond = loot, dot = threat) and colour carries the kind. Stations are excluded on purpose: a fixture the player has learned once is noise on every sweep. The enemy path must `delete blip.drop` or a stale tag draws an enemy as loot.
- **Salvage pops carry a `SAL` tag** (`Hud.popScore(amount, salvage)`): score and salvage both float up at the crosshair, so without the tag a 12-salvage drop reads exactly like a 12-point hit. The flag also toggles `is-salvage` for the gold colour.
